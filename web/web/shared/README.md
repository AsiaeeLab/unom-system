# Shared model scorer

`scorer.js` evaluates a model file (`docs/interface/model_spec.md`) on a FHIR R4 bundle in the browser. It is a line-by-line port of the Python reference `model/reference/score_fhir.py`, which is the ground truth: `web/test/scorer.test.js` checks every vector in `model/test_vectors/expected/` against it to 1e-9 (in practice the outputs are bit-identical). No dependencies, no network calls, and no patient data leaves the page.

## Files the site serves

| Path | Source | Contents |
|---|---|---|
| `/shared/scorer.js` | this folder | the scorer (ES module) |
| `/models/longcovid.json` | `model/longcovid.json` | Long COVID model (current version) |
| `/models/longcovid.example.json` | `model/longcovid.example.json` | placeholder model, v0.1.0 |
| `/models/chronicfatigue.json` | `model/chronicfatigue.json` | chronic fatigue card (scoring-date model, spec section 4b) |
| `/models/fibromyalgia.json` | `model/fibromyalgia.json` | fibromyalgia card (scoring-date model) |
| `/models/index.json` | generated by `analysis/build_models_guide.py` | the model registry: id, version, file, size, and SHA-256 of each model file |
| `/data/patients/<name>.json` | `model/test_vectors/bundles/` | the synthetic test bundles (demo patients and eligibility boundary cases) |

Never edit the copies under `web/web/models/` or `web/web/data/patients/`. Change the files in `model/`, then run `bash web/tools/sync_models.sh`. `npm test` fails if the copies drift from `model/`.

## Using it from a page

```html
<script type="module">
  import { scoreBundle } from "/shared/scorer.js";

  const [model, bundle] = await Promise.all([
    fetch("/models/longcovid.json").then((r) => r.json()),
    fetch("/data/patients/james.json").then((r) => r.json()),
  ]);
  const result = scoreBundle(model, bundle, "2024-06-01"); // omit the date to score as of today (UTC)
  if (result.status === "scored") {
    console.log(result.band, result.probability, result.drivers);
  } else {
    console.log("Not scored:", result.reason);
  }
</script>
```

From a SMART launch, build `{ resourceType: "Bundle", entry: resources.map((resource) => ({ resource })) }` from the resources you fetched (Patient, Condition, Encounter, Observation, MedicationRequest, Procedure) and pass that, together with the resource types whose search failed (below). Same-origin `fetch` is allowed by the site's `connect-src 'self'` policy.

## `scoreBundle(model, bundle, asOf?, { unavailable }?)`

`asOf` is a `"YYYY-MM-DD"` string. It defaults to today's date in UTC (the Python reference uses the machine's local date). `unavailable` lists resource types whose FHIR search failed, was forbidden, or was cut short (for example `["Observation"]`); a failed search is not an empty record (`docs/interface/model_spec.md`, section 4c). The clinician dashboard derives it from the data-access list of the SMART record (`unavailableTypes` in `athena/cards.js`), and the CDS Hooks service from the prefetch and its fallback reads. The result is one of:

```jsonc
// not scored: the card does not apply (the reason is shown to the clinician as a plain sentence)
{ "status": "not_scored", "reason": "fewer than 90 days since the COVID-19 index", "index_date": "2024-01-05" }
// (index_date is absent when there is no index event)

// could not score: a resource the model reads could not be read; never show it as a Typical result
{ "status": "could_not_score", "reason": "could not score: Observation unavailable", "index_date": "2024-01-05",
  "unavailable": ["Observation"] }
// (index_date is present when the eligibility rules could be checked)

// scored (James, longcovid.json v1.2.0, as of 2024-06-01; numbers rounded)
{
  "status": "scored",
  "index_date": "2024-01-05",      // day 0 (the scoring date for scoring_date models)
  "score": -7.98,                  // intercept + sum of weight * value
  "probability": 0.0035,           // piecewise-linear calibration of score
  "band": "Typical",               // first risk band with probability <= max_probability
  "times_average": 0.37,           // probability / reference.cohort_base_rate
  "features": { "age_40_49": 1, "sym_cough": 1, "...": 0 },   // every feature id -> 0 or 1
  "drivers": [                     // present features with nonzero weight, largest contribution first
    { "id": "sym_any_cough", "label": "Cough (coded by day 90)", "group": "Symptoms after COVID",
      "contribution": 0.645217,
      "evidence": [{ "resourceType": "Condition", "id": "james-cond-7", "date": "2024-02-01" }] }
  ]
}
```

Nested thresholds (features identical except for `id`, `label`, `weight`, and `threshold`) appear as a single driver: the highest threshold present, carrying the summed contribution. Dates are calendar dates (the first 10 characters of the FHIR value), so results do not depend on the viewer's time zone. Partial FHIR dates are accepted: `YYYY` and `YYYY-MM` on a record are read as the first day they allow, and on `Patient.birthDate` as July 1 and the 15th (`parseFhirDate`; spec section 3).

## Other exports

The Python helpers are exported under camelCase names for pages that need them: `resourceDate`, `parseDate` (the strict scoring-date parser), `parseFhirDate`, `usable`, `requiredResources`, `daysBetween`, `dayNumber`, `todayUTC`, `codings`, `icd`, `hasIcdPrefix`, `hasCode`, `medMatches`, `matches`, `encounterClass`, `testIsPositive`, `findIndex`, `calibrate`, `nestKey`, and the code-system constants (`ICD10`, `SNOMED`, `LOINC`, `RXNORM`, `CPT`, `ICD10PCS`).

## Error behavior

Chart content never makes the scorer throw: partial dates are read as above, a date field that is not a valid FHIR date is skipped (the record is undated if no field holds one), and a `null` medication or result text counts as empty. The scorer throws where the Python reference raises on the inputs a page controls: an `asOf` that is not a full `YYYY-MM-DD` date, or a model file whose risk bands do not cover the probability. Pages catch errors and show "could not score" (`scoreCard` in `athena/cards.js`; `buildCards` in the CDS Hooks service returns a could-not-score card).
