Developer documentation

The condition cards run versioned JSON model files through one scorer. You can call the scorer from an EHR through the CDS Hooks service, launch the clinician view as a SMART on FHIR app, or run the scorer and the model files in your own code. Synthetic test patients with expected outputs let you check any implementation.

CDS Hooks service

A stateless CDS Hooks 2.0 service for the patient-view hook. It scores the prefetched chart with the Long COVID 1.2.0, Chronic fatigue and ME/CFS 1.0.0, Fibromyalgia 1.0.0, Endometriosis 1.0.0, Lyme 1.0.0, Lupus 1.0.0, Migraine 1.0.0, Depression 1.0.0, and Anxiety 1.0.0 model files and answers with one card for each condition in the High band (indicator warning) or the Elevated band (info), plus one info card naming every condition it could not score. Typical and not-scored results give no card, so a chart with nothing to flag gets {"cards": []}.

The service runs at https://undiagnosednomore.org:

MethodPathAnswer
GET/cds-servicesThe discovery document
POST/cds-services/invisible-illness{"cards": [...]}
OPTIONSboth204 with the CORS headers (Access-Control-Allow-Origin: *), so browser clients such as the CDS Hooks sandbox can call the service

1. Discovery

The service id is invisible-illness. The prefetch templates ask for the Patient and one search each for Condition, Encounter, Observation, MedicationRequest, and Procedure.

bash
curl -s https://undiagnosednomore.org/cds-services
Response

2. Request

FieldRequiredWhat the service does with it
hookyesMust be patient-view; any other hook gets 400.
hookInstanceyesA nonempty string (the examples use a UUID).
context.patientIdyesA FHIR id. The prefetched Patient must have this id, and every prefetched resource whose subject or patient names a patient must name this one; otherwise 400.
context.userIdnoA string if present; not used for scoring.
prefetchnoThe keys from discovery. patient holds the Patient resource; the other keys hold searchset Bundles.
fhirServer, fhirAuthorizationnoUsed only to read prefetch keys the client did not send and the next pages of prefetched searches, and only when fhirServer is on the deployment's allow-list. The token is sent as a bearer token. The default list holds only the synthetic SMART Health IT sandbox, https://launch.smarthealthit.org/v/r4/.
extension["org.undiagnosednomore.scoring-date"]noThe scoring date, YYYY-MM-DD; without it the service scores as of today (UTC). The examples set June 1, 2024, the date of the test vectors.

The example requests are test patients from the test vectors with the prefetch the service asks for: maria.json, elena.json, and maria-missing-observations.json. To send one:

bash
curl -s https://undiagnosednomore.org/developers/examples/maria.json |
  curl -s -X POST https://undiagnosednomore.org/cds-services/invisible-illness \
    -H "Content-Type: application/json" --data-binary @-

Errors and incomplete data

  • 400 with {"error": "..."} for a request that fails the checks above, or a body that is not JSON.
  • 412 when the Patient resource is not in the prefetch and cannot be read from an allowed fhirServer.
  • 502 when the FHIR server returns data for another patient.
  • A search that failed, was forbidden, or was cut short is never read as an empty record. A searchset holding an OperationOutcome with an error, a next link the service may not follow, a total above the entries returned, or more than 10 pages makes that resource type unavailable, and the models that read it get the could-not-score card shown above.

Authentication and logging

The service does not authenticate callers, so it is for synthetic data such as the examples here. A deployment with real patient data must verify the CDS client's signed JWT before handling the request (CDS Hooks 2.0, "Trusting CDS Clients") and limit the allow-list to that client's FHIR base URL. The service code keeps no copy of a request and does not log request bodies.

SMART on FHIR app

The clinician view runs as a SMART on FHIR EHR-launch app with the five condition cards and the timeline of the clinician demo. The EHR opens the launch URL with iss and launch. What the app reads

The Patient, then one search per resource type with _count=100, following next links on the same server: Condition, Observation, DiagnosticReport, Specimen, Encounter, MedicationRequest, MedicationDispense, MedicationAdministration, MedicationStatement, ServiceRequest, Procedure, QuestionnaireResponse, DocumentReference, ImagingStudy, Immunization, AllergyIntolerance, CarePlan, Goal, and FamilyMemberHistory. A search that is denied or not supported marks that type unavailable, and a chart model that reads it shows "Could not score" instead of a result. Resources labeled NOAUTH in meta.security are left out. The model files read six of these types (FHIR inputs).

Scorer library

Two implementations of the same rules, with no dependencies: model/reference/score_fhir.py, the reference that produced the expected outputs (Python standard library only), and /shared/scorer.js, an ES module port for the browser and Node. Both take a model file, a FHIR R4 Bundle of one patient's resources, and a scoring date.

JavaScript

JavaScript
import { scoreBundle } from "/shared/scorer.js";

const model = await (await fetch("/models/longcovid.json")).json();
const bundle = await (await fetch("/developers/vectors/bundles/maria.json")).json();
const result = scoreBundle(model, bundle, "2024-06-01");
// { status, reason, band, probability, times_average, drivers }

The date is a YYYY-MM-DD string; without it the scorer uses today's date in UTC. When a FHIR search failed or was forbidden, pass its resource type so the scorer does not treat the missing records as absent:

JavaScript
const result = scoreBundle(model, bundle, "2024-06-01", { unavailable: ["Observation"] });
// {
//   status: "could_not_score",
//   reason: "could not score: Observation unavailable",
//   index_date: "2024-01-08",
//   unavailable: ["Observation"]
// }

Python

bash
python3 model/reference/score_fhir.py model/longcovid.json \
  model/test_vectors/bundles/maria.json --as-of 2024-06-01
# a failed search: --unavailable Observation,Procedure

In Python the same call is score_bundle(model, bundle, as_of, unavailable=[...]), with as_of a datetime.date.

Model contract

A model file is a linear score over named, dated chart findings, with a calibration map and risk bands, so every point of the score traces to a chart resource. Its top-level fields:

FieldHolds
model_id, version, statusIdentity: a stable id, a semantic version, and research or placeholder
targetWhat the model predicts (label, definition) and for whom (population); for an index-event model, landmark_days and horizon_days
index_eventDay 0: the codes of the index event, or "type": "scoring_date"
exclusionCodes that mean the target diagnosis is already recorded, so the chart is not scored
eligibilityOptional: the FHIR gender a model is limited to (sex) and the reason shown otherwise; the endometriosis model covers women
history_requirementScoring-date models: the encounters a chart needs in a window to be scored
windowsNamed day ranges relative to day 0
featuresEach with an id, label, group, kind, codes or classes, windows, and weight
intercept, calibration, risk_bandsThe score, its piecewise-linear map to a probability, and the bands by upper probability
referencecohort_base_rate, the denominator of "times the average"
provenance, statementData, method, and validation; the sentence shown with every result
Scoring
score       = intercept + Σ weight_j × value_j        (each value is 0 or 1)
probability = calibration(score)                      (piecewise-linear, clamped at the ends)
band        = first risk band with max_probability ≥ probability

Features come in nine kinds: any, new_onset, encounter_any, encounter_count_ge, encounter_rate_ratio_ge, derived_count_ge, cluster_count_ge, age_band, and sex. The interface spec defines each, with the date rules and the order of the eligibility checks.

The contract is at version 0.2. Its full text is the interface spec.

FHIR inputs

The scorer reads FHIR R4 Patient, Condition, Encounter, Observation, MedicationRequest, and Procedure resources. A coding matches only when its system is exactly one of these URIs:

  • Encounters count by class.code: AMB, EMER, and IMP (HL7 v3 ActCode); virtual (VR) and home (HH) visits count as AMB.
  • Patient: birthDate gives the age on day 0 (days / 365.25; under 18 is not scored), and gender the sex feature.
  • Dates come from the first valid field of onsetDateTime, onsetPeriod.start, recordedDate, period.start, effectiveDateTime, effectivePeriod.start, issued, authoredOn, performedDateTime, performedPeriod.start, and occurrenceDateTime, as calendar dates (time and zone ignored). YYYY and YYYY-MM are read as the first day they allow, and as July 1 and the 15th on birthDate.
  • Ignored: records dated after the scoring date; Conditions whose verificationStatus is refuted or entered-in-error; any record whose status is entered-in-error. An undated record falls in no window, but an undated target diagnosis still counts as already recorded.
  • Missing records count as absent (value 0), as in training. A search that could not be read is different: pass it as unavailable (spec, section 4c).

A scorer passes a vector when, run with the vector's as_of date, its result has the same fields as the expected output (without as_of), every number agrees to 1e-9, and everything else is identical: status, reason, band, each feature value, and the drivers in order with their evidence. Beyond the demo patients, the vectors cover the eligibility rules: a Long COVID code before the index, on the index date, on day 90, or undated; an index more than 455 days back; partial dates, an infection before July 2, 2021, and refuted or future-dated codes; no birth date; and a patient under 18.

# rebuild the bundles and one model's expected outputs with the reference scorer
python3 model/test_vectors/make_bundles.py model/longcovid.json

# check the JavaScript scorer and the CDS Hooks service against them
cd web && npm test

The bundles are FHIR R4 collection Bundles whose fullUrl values are name-based urn:uuid: UUIDs. Where the HL7 FHIR validator is installed: java -jar validator_cli.jar -version 4.0.1 model/test_vectors/bundles/*.json.

Versioning

  • Each model file carries its model_id and a semantic version. The CDS Hooks card names both, and so does /models/index.json.
  • Expected outputs are stored per version in model/test_vectors/expected/<model_id>-<version>/. The directories of superseded versions stay in the repository.
  • Model files are served with Cache-Control: public, max-age=300, so a cached copy is at most five minutes old.
  • python3 analysis/build_release_manifest.py --out <file> records each deployed model file's hash and version, the scorer hashes, and the contract version.
